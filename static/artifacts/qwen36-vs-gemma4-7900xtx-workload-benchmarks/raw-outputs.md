# Postmortem: API Latency Spike & DB CPU Exhaustion Due to Unbounded Export Query

## Incident Summary
At 14:02 UTC, API p99 latency spiked from 80ms to 9 seconds with a 12% error rate due to database CPU exhaustion. The incident was caused by an unbounded report export query originating from a feature released two days prior. The on-call team identified and terminated the query, disabled the feature via flag, and restored normal service within 18 minutes. No data loss occurred.

## Timeline (All times UTC)
- **14:02** – API p99 latency jumps to 9s; error rate reaches 12%; database CPU pins at 100%.
- **14:05** – On-call engineer paged via performance alerts.
- **14:11** – Root cause identified: a single report export query scanning the full `orders` table without a `LIMIT`, triggered by a newly shipped “export all” button. No deploys had occurred in the prior 6 hours.
- **14:14** – On-call terminates the blocking query.
- **14:15** – API latency recovers to baseline (~90 seconds post-kill).
- **14:20** – Export feature disabled via feature flag; full service restoration confirmed.

**Total degraded time:** 18 minutes  
**Data impact:** None  

## Root Cause Analysis
The incident resulted from a single unbounded database query monopolizing shared resources, compounded by missing operational guardrails around bulk data operations.

- **Direct Trigger:** A customer request to the new “export all” endpoint executed a full-table scan on the `orders` table without a row limit or pagination, consuming nearly 100% of database CPU.
- **Contributing Factors:**
  1. **Missing Endpoint Safeguards:** The export feature shipped without pagination, rate limiting, or hard query timeouts.

*Action items are organized by timeframe and ownership context. All items focus on system design, process safeguards, and monitoring improvements.*

**Process & Long-term (Owner: Engineering Leadership / SRE)**
